# L121 No Code / Low Code

## 判斷句

- **No Code**：幾乎不寫程式，用畫面、流程、範本組應用。
- **Low Code**：少量程式／表達式補足，仍以視覺化為主。
- 優勢：快、業務可參與、降低工程瓶頸。
- 限制：客製天花板、廠商鎖定、權限與稽核、效能與資安不透明。
- **治理不會因為 No Code 而消失。** 個資、權限、測試、問責一樣要做。

## 何時用、何時不用

| 較適合 | 較不適合 |
|--------|----------|
| 內部試作、表單、簡單自動化 | 核心交易、高風險核決、複雜整合 |
| 標準連接器就夠 | 要深度客製協定或嚴格延遲 |
| 要讓業務先跑通流程 | 要可移植、避免單一雲鎖定 |

## 易混

- Copilot／Cursor 幫你寫 code ≠ 整個專案變成 No Code。
- 能做出 Demo ≠ 能上生產（權限、log、備援、資料落地）。

## 樂雲場景

業務要自己做 GPT 客服：可用 Low Code 試點，但客戶資料、提示外洩、升級路徑要規劃師先畫紅線。

## 自測

1. 兩週內驗證「工單自動分類」值不值得做，No/Low Code 合理嗎？  
2. 核心計費引擎用純 No Code 拼，最大風險是哪三個？  
3. Low Code 上線後要換供應商，規劃時該先問什麼？

參考：1 合理（試點） 2 鎖定、稽核、效能／正確性 3 資料可匯出、標準 API、契約退出
