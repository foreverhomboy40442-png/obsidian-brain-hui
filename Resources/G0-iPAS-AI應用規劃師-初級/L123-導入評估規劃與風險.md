# L123 導入評估、規劃與風險

## 判斷句

- 導入順序：**問題與目標 → 資料能不能用 → 方案選擇 → 成本效益 → 試點測試 → 權限與監控 → 擴大。** 先選模型是錯序。
- 評估要能講 **ROI／TCO**（效益 vs 總持有成本：授權、token、人、風險事故）。
- 風險三大塊：倫理與偏誤、資料安全隱私、合規與智財（生成內容著作權、幻覺當事實）。

對照文件方向：經濟部產業發展署《AI 導入指引》、公部門手冊、金管會金融 AI 指引（看場景選）。

## 評估（L12301）

要能回答：

1. 這題該不該用 AI？（規則引擎是否就夠）  
2. 鑑別／生成／RAG／Agent 哪個夠用？  
3. Buy vs Build vs 既有雲服務  
4. 成本：API token、人力覆核、失敗代價  
5. 效能：延遲、正確率下限、可否離線

## 規劃（L12302）

- 目標要可量測（例如：工單初判正確率、平均處理時間）。
- 資源：資料負責人、覆核人力、資安、預算。
- 策略：小範圍試點 → 成功條件 → 再擴大。
- 測試：功能、資安、提示注入、回歸；高風險加人工抽樣。

## 風險（L12303）

| 風險 | 規劃師動作 |
|------|------------|
| 個資外流到公有模型 | 禁傳、私有化、最小化、契約與 log |
| 幻覺被當官方回覆 | RAG、引用、低 temperature、人工放行 |
| 提示注入／外洩系統提示 | Guardrail、權限分離、不把秘密放進 prompt |
| 偏誤歧視 | 資料審查、監控、申訴與人工覆核 |
| 智財 | 訓練／輸出授權、標示 AI 生成 |
| 問責不清 | RACI：誰能上線、誰能覆核、誰能關機 |

## 易混

- 試點成功 ≠ 全面上線（權限、備援、營運人力沒跟上）。
- 便宜模型省 token，可能增加人工覆核成本 → TCO 未必低。

## 樂雲場景

客戶要「全公司一個 GPT」：先分類資料敏感度與使用場景，給分級方案（公開網 → 內部知識 RAG → 禁止上傳），再談工具名。這同時對齊你的 M1（企業 AI 治理）。

## 自測

1. 寫出導入七步（自己的話，順序對即可）。  
2. 只比 API 單價、忽略覆核人力，錯在哪？  
3. 業務要把客戶名單貼進公有 LLM 做話術，第一個控制是什麼？

參考：1 問題→資料→選方案→成本→試點→權限監控→擴大 2 忽略 TCO 3 禁止／資料最小化與出域控制
